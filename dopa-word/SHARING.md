# 공개 단어장과 즉시 공유 링크

## 다른 사람이 바로 보는 두 가지 방법

**공개 단어장**은 사이트의 ‘공개 단어장’에서 누구나 볼 수 있는 목록입니다. GitHub 저장소의 `dopa-word/shared/catalog.json`에 공개용 단어·뜻을 저장합니다. 방문자는 로그인하거나 JSON 파일을 가져오지 않고 곧바로 스펠링·뜻 고르기를 실행합니다.

**바로 전달할 링크**는 선택한 단어장의 내용을 URL의 `#words=` 부분에 담습니다. GitHub 로그인 없이 만들어 메신저로 전달할 수 있습니다. 받은 사람은 링크를 열어 단어와 뜻을 확인하고 두 모드를 실행합니다. 링크를 안다는 사실은 작성자 인증이나 비밀 접근 권한이 아닙니다. 다른 사람에게 재전달할 수 있고, 원본을 수정해도 이미 보낸 링크는 바뀌지 않습니다. 이 링크만 만들었다고 공개 목록에 자동 등록되는 것은 아닙니다.

두 방식 모두 개인 점수·오답·학습 기록·설정·다른 비공개 카테고리를 공유 데이터에 넣지 않습니다. 기존의 개인 저장 버튼은 계속 개인 저장입니다.

## 내 단어를 공유하는 순서

1. 홈의 **내 단어 공유하기** 또는 단어장 관리의 **선택한 카테고리 공유하기**를 누릅니다.
2. 공유할 카테고리·공개 제목·단어 수와 미리 보기를 확인합니다. 개인정보, 비밀, 재배포 권한 없는 자료를 넣지 않습니다.
3. 공개 동의에 체크한 뒤 **바로 전달할 링크 만들기**로 링크를 만들고 복사하거나 메신저로 보냅니다.
4. 사이트의 공개 목록에도 올리려면 **GitHub 공개 등록 준비 → GitHub에서 제출하기 → Submit new issue**를 누릅니다. 현재 공개 목록 게시 권한은 저장소 소유자 `dalmook`에게만 있습니다. 다른 사람은 로그인 없이 읽고 학습하거나 자신이 만든 링크를 전달할 수 있습니다.

공개 등록 준비는 아직 저장 완료가 아닙니다. 실제로 GitHub 요청을 제출해야 자동화가 실행됩니다. 내용이 길면 자동 채우기 대신 화면의 ‘등록 내용 복사’를 눌러 요청 본문에 붙여 넣습니다. Actions 완료 댓글에 공유할 고정 링크가 나옵니다.

## 기존 공개 단어장 수정과 내리기

공개 카드의 **등록 내용·수정·내리기**에서 원래 GitHub 요청을 열 수 있습니다. 앱에서 새로운 공개 내용을 복사하여 원래 요청 본문의 `dopa-word` 코드 블록을 수정하면 동일한 공개 링크에 새 버전이 저장됩니다. 동일 제목의 현재 공개 항목이 목록에 로드되어 있으면 앱도 기존 요청을 안내합니다.

그 요청을 **닫으면** 공개 목록에서 내려갑니다. 다시 **열면** 해당 요청의 현재 내용으로 다시 게시됩니다. 삭제 요청의 의미는 목록에서 내리는 것이며, GitHub의 이전 커밋·요청 이력과 이미 받은 사람의 링크·내 단어 복사본·보관본까지 지우는 기능은 아닙니다. 민감한 정보를 공개했다면 별도 삭제·이력 정리가 필요합니다.

## 저장·읽기 구조

개인 데이터는 기존 `localStorage['dopa-word-ko-v1']`을 유지합니다. 다른 사이트 방문자에게 자동 전송하지 않습니다. 같은 기기의 같은 브라우저 프로필을 쓰는 사람은 개인 데이터도 볼 수 있습니다.

공개 데이터를 학습할 때는 단어에 `shared:<단어장번호>:<영어>`라는 별도 식별자를 사용합니다. 같은 영어라도 내 단어의 뜻과 학습 기록을 덮어쓰지 않습니다. 두 모드의 개인 학습 기록은 각각 저장합니다. 학습한 공개 단어장은 이 브라우저에 보관하여 재접속 후 기록을 이어갈 수 있으며, ‘보관본 지우기’는 해당 공개 단어장의 로컬 보관본·로컬 학습 기록만 지웁니다.

공개 내용을 **내 단어장에 복사**할 때는 이미 있는 영어를 건너뛰고 기존 개인 뜻을 보존합니다. 복사한 개인 단어를 수정해도 공개 원본이 바뀌지 않습니다. 최신 공개본으로 학습하려면 공개 목록에서 다시 선택합니다. 내려간 단어장도 이미 받은 보관본은 남을 수 있으며 화면에서 이를 구분합니다.

## GitHub Actions

- 워크플로: `.github/workflows/dopa-word-publish.yml`.
- GitHub 소유자 계정이 작성한 `[단어공개]` 요청의 생성·본문 수정·열기·닫기를 처리합니다. 소유자가 수동 실행할 때는 요청 번호만 전달합니다.
- 실행 전 신뢰할 수 있는 기본 브랜치의 코드를 체크아웃하고, 서버에서 GitHub 작성자·이벤트 발신자 ID를 모두 다시 검사합니다. 다른 방문자가 공개 목록을 임의 수정할 수 없습니다.
- 브라우저에 GitHub 토큰이나 공통 비밀번호를 넣지 않습니다. Actions의 일시적인 `GITHUB_TOKEN`은 워크플로 안에서만 사용합니다.
- 요청 텍스트를 쉘 명령이나 코드로 실행하지 않습니다. 정해진 JSON 형식의 제목·단어·뜻만 허용하고 공개 목록 파일 하나만 갱신합니다. 동시 게시 시 현재 SHA로 충돌을 확인하고 재시도합니다.
- 공개 목록은 GitHub의 raw JSON에서 읽어 GitHub Actions 자체 커밋이 Pages 재빌드를 유발하지 않아도 갱신됩니다. 네트워크에 따라 반영 지연이 있을 수 있고 ‘공개 목록 새로고침’을 제공합니다. 원격 연결이 실패하면 사이트 배포 시점의 목록 또는 기기의 보관본이라는 상태를 명확히 표시합니다.

공개 단어장 하나에 최대 500단어, JSON 48KB, 즉시 링크는 전체 길이 12,000자까지입니다. 더 크면 카테고리를 나누어야 합니다. 공개 목록 최대 100개, 기기 보관본 최대 12개입니다. 한도 초과 때 기존 단어장을 몰래 삭제하지 않습니다.

## 검증 범위

단위 검사에는 공유 필드 최소화, 악성·잘못된 입력, 작성자 검증, 여러 게시의 보존, 수정·내리기·재게시, 충돌을 피하는 단어 ID, 기존 v1 백업 호환성을 포함합니다. 브라우저 회귀 검사는 기존 두 모드·카테고리 기능에 더해 다른 브라우저의 링크 열기·전체 학습·저장과 공개 목록 UI를 확인합니다. 목록 UI 테스트는 합성 자료를 사용하며, 실제 운영 게시 자동화는 별도로 실제 소유자 요청과 결과 파일로 확인합니다.

기존 산수·OX·토리 게임과 원작 캐릭터·음악 파일은 변경하지 않습니다. 원작의 비공식·비영리 이용 조건은 `LICENSE`를 따릅니다.
