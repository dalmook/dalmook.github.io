# WordBunny Island · 워드버니 아일랜드

**나의 단어와 사진으로 만드는, 아이의 작은 영어 모험.**

`heather_word`와 무관한 독립 프로젝트입니다. 기존 앱의 파일·라우트·학습 기록을 수정하거나 가져오지 않습니다. 이름, 화면, 단어 관리, 학습 엔진, 데이터 저장소를 새로 구성했습니다.

## 웹에서 실행하기

배포 대상: https://dalmook.github.io/wordbunny-island/

소스 위치: https://github.com/dalmook/dalmook.github.io/tree/main/wordbunny-island

이 앱은 기존 단어앱에 붙인 화면이 아닙니다. 개인 Pages 저장소 안의 독립 폴더이며 자체 코드와 데이터 저장소를 사용합니다. 전용 새 저장소를 만든 것은 아닙니다.

## 파일로 실행하기

`OPEN_WORD_BUNNY.html`을 브라우저에서 열면 됩니다. 스타일·스크립트·48개 단어 그림이 한 파일 안에 들어 있어 설치나 외부 라이브러리 없이 사용할 수 있습니다. HTML 미리보기만 제공하는 앱에서는 파일을 저장한 뒤 실제 브라우저로 열어 주세요.

이 단일 파일 버전은 내장 콘텐츠를 사용하는 독립 실행판입니다. GitHub의 새 단어팩을 자동으로 불러오는 버전이 아닙니다. 파일 열기 방식에서 영구 저장을 허용하지 않는 브라우저는 안내 배너가 표시되므로 종료 전에 백업하세요. 파일 이름·경로 변경, 브라우저 데이터 삭제, 시크릿 모드 등에 따라 저장 자료가 유지되지 않을 수 있습니다.

폴더 기반 버전을 실행하려면 Python 3가 설치된 Windows에서 `START.cmd`를 실행하거나 다음 명령을 사용합니다.

```sh
python scripts/serve.py
```

`127.0.0.1:8080`에서만 열리며 다른 기기에 공개하지 않습니다. 포트가 사용 중이면 `python scripts/serve.py --port 8081`을 사용하세요.

## 들어 있는 것

| 화면 | 실제 기능 |
|---|---|
| 모험 홈 | 오늘의 5단어 소개 → 혼합 문제, 복습 대기 단어, 목표·XP·학습일 |
| 내 단어장 | 영어·뜻·주제·사진·예문 등록/수정, 검색, 즐겨찾기, 주제 필터, 일괄 입력 |
| 놀이 광장 | 그림 탐정, 소리 숲, 철자 공방, 짝꿍 카드, 둥실 풍선, OX, 뜻 찾기, 혼자 써보기 |
| 버니와 친구들 | 원본 흰 토끼 일러스트, 6가지 꾸미기, XP로 만나는 6친구 |
| 성장 기록 | 도전/정답/숙련 단계, 날짜별 기록, CSV, 사진 포함 백업·복원 |

기본 콘텐츠는 음식·동물·학교·일상 4주제, 48개 단어입니다. 기본 이미지는 이 프로젝트용 벡터 그림이며 사용자 사진으로 교체할 수 있습니다. 주제와 단어는 고정 교육과정이 아닌 시작용 예시입니다.

## 단어와 사진 넣기

`내 단어장 → 단어 추가`에서 보호자 확인 후 영어와 뜻을 입력하세요. 사진, 주제, 쉬운 예문은 선택 사항입니다. 보호자 확인은 실수로 편집하는 것을 줄이는 산수 문제이며 보안 인증이나 비밀번호가 아닙니다.

사진은 JPG·PNG·WebP, 입력 파일 최대 12MB입니다. 긴 변 960px 이내로 줄여 저장합니다. 사진 없는 단어도 뜻·철자 문제로 학습할 수 있습니다. HEIC는 먼저 JPG로 변환해야 합니다. 사진 업로드는 **브라우저 안에 저장하는 것**이며 서버·GitHub로 자동 전송하지 않습니다.

`여러 단어`에서는 CSV, TSV, TXT, JSON 또는 아래 형식을 사용하세요.

```text
apple / 사과
rabbit / 토끼
```

영어/뜻/주제/예문 열을 엑셀에서 복사해 붙여 넣을 수도 있습니다. 확인 화면에서 중복과 추가 수를 검토한 후 저장합니다. 한 번의 입력은 1,000단어, 기기에 저장하는 사용자 단어는 최대 10,000개로 제한합니다. 사진 용량과 기기 저장 공간이 실질적인 한계이며 대용량 저장 성능은 별도 검증이 필요합니다.

## GPT로 GitHub 콘텐츠 업데이트

핵심은 **코드는 그대로 두고 `content/`만 관리하는 구조**입니다. 전체 안내는 `content/AGENTS.md`, 요청 예시는 `CONTENT_WORKFLOW.md`에 있습니다.

```text
content/manifest.json          단어팩 목록
content/packs/*.json           영어, 뜻, 주제, 이미지 경로, 예문
content/images/*               사진과 그림
```

단어 ID는 학습 기록의 키입니다. 같은 단어의 사진·예문을 수정할 때 ID를 바꾸지 마세요. 전혀 다른 단어는 새 ID로 만듭니다. 그림 경로는 저장소 내부 상대경로만 허용합니다.

GitHub 폴더 기반 앱은 새로 열 때 콘텐츠 목록을 확인합니다. 보호자 공간에서 수동 새로고침도 할 수 있습니다. 네트워크 실패 시 기존 내장/저장 콘텐츠를 유지합니다. **같은 ID의 기기별 수정본이 있으면 기기 수정본이 GitHub 원본보다 우선**합니다.

`GitHub용 ZIP`에는 현재 앱에서 보이는 전체 단어와 관련 이미지가 들어갑니다. 개인 이름·XP·학습 기록은 제외합니다. 기존 저장소에 적용할 때는 비교·병합해야 하며 `manifest.json`을 무조건 덮어쓰지 마세요. 1,000단어를 넘으면 자동으로 여러 팩으로 나눕니다.

## 백업과 기록

`성장 기록 → 전체 백업`은 사용자 단어/사진, 로컬 수정본, 즐겨찾기, 숨김 상태, 꾸미기, 설정, 학습 기록을 JSON에 저장합니다. 저장소의 기본 단어팩은 앱 콘텐츠로 별도 관리합니다. 개인 정보가 포함될 수 있는 백업 JSON은 공개 GitHub에 올리지 마세요.

`복원`은 현재 기기의 로컬 자료를 선택한 백업 내용으로 교체하므로 확인 후 진행해야 합니다. 다른 기기에 자동 동기화하지 않습니다. 사진·기록이 중요하면 주기적으로 백업을 보관하세요.

## 학습 규칙

정답은 XP와 별코인을 주고, 오답은 정답을 보여 준 뒤 다시 만납니다. 오답·힌트 문제는 한 세션에서 최대 한 번 추가되어 끝없이 반복하지 않습니다. 같은 날 반복 정답만으로 기억 단계를 올리지 않으며, 복습 시점이 된 다른 날의 독립 정답이 단계 상승 조건입니다. 단계별 다음 간격은 1·3·7·14·30일입니다.

초기 모험은 최대 5단어를 소개한 뒤 두 번씩 섞어 출제합니다. 일반 놀이는 선택한 단어 중 최대 10개, 짝꿍 카드는 최대 4쌍입니다. 단어가 적으면 분량도 줄어듭니다. 사진이 없거나 음성 API가 없는 환경에서는 가능한 문제 형태로 대체합니다. 음성 API가 있어도 실제 음성 재생에 실패하는 경우에는 안내를 표시하며 뜻 찾기를 사용할 수 있습니다.

난이도 태그는 관리용 메타데이터입니다. 발음 평가 AI, 학년별 공인 교육과정, 과학적으로 검증한 개별 최적 복습 모델이라고 주장하지 않습니다. 본 구현의 간격 규칙은 명시적인 단순 휴리스틱입니다.

## 음성·효과·접근성

영어 읽기는 기기의 `speechSynthesis`를 사용합니다. 녹음하거나 음성 인식 점수를 계산하지 않습니다. 기기/브라우저에 따라 목소리, 사용 가능 여부, 오프라인 재생이 다릅니다. 설정에서 속도, 효과음, 생성 멜로디, 움직임 줄이기를 변경할 수 있습니다. 기기 TTS 서비스의 내부 동작까지 이 앱이 통제하지는 않습니다.

키보드 탐색, 모달 포커스 제한, Escape 닫기, reduced-motion 처리가 들어 있습니다. 모든 보조기술 조합이나 접근성 인증을 완료한 것은 아닙니다.

## 배포 구조

`dalmook/dalmook.github.io` 저장소의 `wordbunny-island/`에만 앱 파일을 둡니다. `heather_word`와 기존 홈페이지/다른 게임 파일은 수정하지 않습니다. 루트에는 이 앱의 검증 워크플로 하나만 추가합니다.

콘텐츠를 바꿀 때는 `cd wordbunny-island` 후 검증과 `python scripts/build.py`를 실행하고, 단어팩/이미지와 생성된 starter·서비스 워커·단일 HTML을 함께 커밋하세요. 실제 배포 상태는 저장소의 Actions와 웹 주소에서 확인합니다.

기기 백업, 학습 기록, API 키, 얼굴·실명·학교 정보가 포함된 사진은 공개 저장소에 올리지 않습니다.

## 개발·검증

런타임 npm 패키지는 필요 없습니다. Node 20 이상과 Python 3를 사용합니다.

```sh
node scripts/validate-content.cjs
node --test tests/core.test.cjs
python scripts/build.py
```

브라우저 검사에는 Python Playwright와 Chromium이 필요합니다. 설치된 실행 파일 경로는 테스트 코드 하단을 확인하세요.

```sh
python tests/browser.test.py editor
python tests/browser.test.py learning
python tests/browser.test.py screens
```

이번 환경에서는 브라우저 URL 이동이 차단되어 단일 HTML을 `page.set_content()`로 렌더링해 검사했습니다. **실제 origin의 IndexedDB 재접속 유지, 서비스 워커, 실제 스피커 출력, GitHub 실배포, 실물 휴대폰 조작은 검증하지 못했습니다.** 통과 범위를 `QUALITY_REPORT.md`에 구분해 기록했습니다.

`build.py`는 `js/starter.js`, `sw.js`, `OPEN_WORD_BUNNY.html`을 다시 만듭니다. 콘텐츠를 바꾼 뒤 반드시 실행하세요. PWA 캐시는 이 앱의 scope만 관리하며 다른 앱 캐시를 삭제하지 않습니다.
